# WireGuard на Mini 3

Проверено на Mini 3 YNDX-00027 (Bergamot). Персональные адреса исходной установки удалены. Собственные параметры задаются через локальный конфиг.

## Причины исходных сбоев

- DHCP удалял маршрут до endpoint из основной таблицы: UDP самого WireGuard попадал обратно в wg0.
- Vendor hook `21-unbound.conf` переписывает resolv.conf. Одного `nohook resolv.conf` недостаточно.
- После перезагрузки время может быть неверным. До подключения туннеля нужен доступ к NTP напрямую.
- BusyBox ip не принимал таблицу 51820; использована таблица 200.

## Настройка

1. Сохраните резервные копии `/etc/dhcpcd.conf`, `/etc/dhcpcd.exit-hook`, `/etc/chrony.conf` и VPN init-скрипта вне Git.
2. Скопируйте `config/network.conf.example` в `/data/opt/etc/wireguard/network.conf`, заменив все демонстрационные адреса. TEST-NET в примере предназначен для документации и не обеспечит подключение.
3. Каталог должен принадлежать root и иметь режим 700, конфиг — root:root и 600. Это shell-файл, выполняемый root: не используйте недоверенные конфиги.
4. Приватный WireGuard-конфиг сохраните отдельно как `/data/opt/etc/wireguard/wg0.conf` с режимом 600. Требуется формат `wg setconf`, без полей wg-quick `Address`, `DNS`, `PostUp` и т. п. Адрес и DNS задаются в network.conf. Скрипт рассчитан на один peer с endpoint; hostname заменяется заданным IPv4.
5. Установите `wireguard-go` и `wg` в `/data/opt/bin`, проверьте наличие `/dev/net/tun` и работающего chronyd/chronyc.
6. После проверки параметров установите `S98mini3wg.v2` как `/etc/init.d/S98mini3wg` с режимом 755. Фрагмент `mini3-dhcpcd.exit-hook` добавьте в существующий exit-hook, сохраняя другие настройки.
7. В `/etc/dhcpcd.conf` нужны `nohook resolv.conf unbound.conf` и `denyinterfaces wg0`. Числовой NTP-сервер должен быть доступен напрямую; init-скрипт добавляет его в chrony при запуске.

Параметры: `ENDPOINT`, `ENDPOINT_PORT`, `NTP`, `GATEWAY`, `LAN_CIDR`, `LAN_INTERFACE`, `VPN_ADDRESS`, `MTU`, `DNS`. Для альтернативного root-owned конфига можно задать `MINI3_WG_CONFIG`; DHCP hook использует стандартный путь.

## Маршрутизация и ограничения

- Правила 100/101 отправляют endpoint и NTP через таблицу 200 и LAN-шлюз. Эти номера должны быть свободны и выделены скрипту; проверьте `ip rule show` и таблицу 200 перед установкой.
- Интернет IPv4 идёт через два маршрута `/1` в wg0; локальная сеть остаётся доступной напрямую.
- DHCP hook восстанавливает DNS и policy routes после изменения аренды LAN.
- Нативный IPv6 выключается при старте туннеля на устройстве целиком.
- Endpoint и NTP закреплены числовыми IP; обновляйте локальный конфиг при смене сервисов.
- Это не kill switch: до запуска или после исчезновения VPN-интерфейса возможен прямой доступ через обычный default route.
- Команда `stop` не реализована: откат сетевых настроек требует учёта конкретной конфигурации.

## Проверка

```sh
/etc/init.d/S98mini3wg up
/etc/init.d/S98mini3wg status
```

Проверьте свежий handshake, маршрут endpoint через LAN, внешнего адреса через wg0, доступ к локальной сети и DNS после обновления DHCP-аренды. Исходная установка прошла эти проверки также после перезагрузки. Опубликованный вариант с внешним конфигом проверяется изолированно, без изменения работающей колонки.
