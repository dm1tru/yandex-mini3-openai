# OpenAI на Яндекс Станции Мини 3

Сборка 29 октября 2026. Подключение: `ssh -p 2222 root@<STATION_IP>`; адрес и SSH-ключ определяются вашей установкой.

Архитектура сверена с https://github.com/alexrosette/Yandex-Claude-Assistant (commit `4dc56d84ace49587094ffe2aef7465601085d587`): локальный Vosk, отдельный HTTPS-клиент, синтез речи и ALSA. Исходный проект использует Claude Messages API и ElevenLabs, а не Claude Code. Здесь реализован собственный клиент Go со стандартной библиотекой, Responses API и OpenAI Speech API. Патч часов усилителя через /dev/mem из исходного проекта не применяется; используется ранее проверенный PCM `speakers`.

## Управление

```sh
/data/opt/bin/gpt-live start
/data/opt/bin/gpt-live status
tail -F /tmp/gpt-live.log
/data/opt/bin/gpt-live stop
```

После `ready` и одной секунды прогрева скажите: **«Компьютер, сколько будет два плюс два?»**. Можно отдельно сказать «Компьютер», затем в течение 10 секунд произнести вопрос. Для нового вопроса нужно снова обратиться «Компьютер». История диалога пока не передаётся.

## Кнопки и световое кольцо

Сенсорные «+»/«−» управляют ALSA Master с шагом 5 процентных пунктов; удержание поддерживается с ограничением повторов. Обработка кнопок идёт отдельно от запросов и воспроизведения. Зелёные сегменты на секунду показывают громкость (при нуле — один тусклый красный сегмент). На цифровом дисплее две секунды отображается значение громкости от 0 до 100 в процентах, без ведущих нулей. Новое нажатие продлевает показ. Затем восстанавливаются прежняя яркость сегментов и LED triggers.

Кольцо показывает состояния: тусклое белое пульсирование при загрузке; голубой после предварительного распознавания слова обращения; оранжевое пульсирование при запросе ответа и синтезе; зелёный во время проигрывания; красный на 2 секунды при ошибке. В ожидании кольцо выключено. Без последующего вопроса индикация прослушивания гаснет по тайм-ауту. Предварительное распознавание может ошибиться: само по себе оно не отправляет запрос в API.

Контроллер `aw933xx` обнаруживается через sysfs, резервный путь `/dev/input/event1`. `MINI3_INPUT_DEVICE` позволяет указать другой путь. Клиент собран для aarch64 и читает 24-байтные input_event. `MINI3_LED_ROOT` меняет корень `/sys/class/leds` для диагностики. Управляются только `bergamot:{red,green,blue}:logo0..5` и trigger синхронизации кольца. Для временного показа громкости также используются сегменты `bergamot:white:clock*`; после показа они восстанавливаются. Штатные LED triggers временно отключаются и восстанавливаются при штатной остановке сервиса.

Сервис временно останавливает Алису, выставляет PDM Gain 36, включает zram при необходимости. После остановки возвращает Алису, если она работала. Автозагрузка пока не включена. Одновременный запуск с `vosk-live`/`vosk-test` запрещён.

Генерация: `gpt-4.1-mini`, Responses API, `store:false`, до 300 выходных токенов. Озвучивание: `gpt-4o-mini-tts`, голос `coral`, PCM 24 кГц моно, преобразованный в 48 кГц стерео. Голос создан ИИ. Запросы выходят с колонки через её WireGuard. HTTPS проверяет сертификаты; обход проверки не используется.

Ключ: `/data/opt/openai/key.txt`, каталог 700, файл 600. В исходниках, аргументах команд и журналах ключа нет. Не публикуйте локальный `openai-key.txt`. Путь можно изменить через `OPENAI_KEY_FILE`, модель через `OPENAI_MODEL`, голос через `OPENAI_VOICE`, слово обращения через `OPENAI_WAKE_WORD` (одно слово в нижнем регистре).

Распознавание локальное; в OpenAI отправляется текст вопроса после обращения и текст для озвучивания. Во время запросов и проигрывания файл `/tmp/mini3-openai-mute` заставляет Vosk сбрасывать входящий звук; микрофон продолжает обслуживаться. Аудиозаписи не сохраняются. Временный текстовый журнал ограничен примерно 1 MiB (и одна предыдущая копия). Не более 6 вопросов в минуту, тайм-аут API 60 секунд, автоматических повторов платных запросов нет.

## Команды без микрофона

```sh
/data/opt/bin/mini3-openai ask 'Ответь кратко: сколько будет два плюс два?'
/data/opt/bin/mini3-openai say 'Это синтезированный голос.'
/data/opt/bin/mini3-openai talk 'Почему небо голубое?'
```

`say` и `talk` отдельно не заглушают работающий голосовой сервис; для ручных тестов сначала остановите `gpt-live`.

## Исправление Vosk

В журнале ядра подтверждён OOM предыдущего постоянного распознавателя: система убила `vosk-stream` и `arecord`. Новый клиент сбрасывает распознаватель после каждого результата и не позже 15 секунд аудио, чтобы ограничить размер одной сессии декодирования. Увеличен запрашиваемый ALSA-буфер до 1 секунды, период 20 мс; фактические значения зависят от драйвера. Чтение аудио выполняется блоками, FIR использует float. Длительную стабильность нужно оценивать отдельно, короткий тест её не гарантирует.

## Проверки

Успешно выполнен настоящий короткий запрос Responses API с колонки. Запрос Speech API и `aplay` завершились успешно. Тесты Go проверяют заголовок авторизации, разбор массива Responses, скрытие секрета в ошибках, PCM-преобразование и границу слова обращения.

Полная акустическая проверка также прошла: через динамик воспроизведено «Компьютер, сколько будет два плюс два?», микрофон/Vosk распознали вопрос, сервис получил ответ «Два плюс два будет четыре.» и озвучил его без ошибки. На контрольной отметке 83.9 секунд обработанного звука `compute_ratio=0.58`, очередь 0.00 с, новых `overrun` в журнале не было. Фактический ALSA-буфер драйвер ограничил 2048 кадрами при 48 кГц (около 43 мс), период 1024 кадра: увеличение запрошенного буфера не дало секундного запаса.
