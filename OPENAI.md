# OpenAI на Яндекс Станции Мини 3

Сборка 29 октября 2026. Подключение: `ssh -p 2222 root@<STATION_IP>`; адрес и SSH-ключ определяются вашей установкой.

Архитектура сверена с https://github.com/alexrosette/Yandex-Claude-Assistant (commit `4dc56d84ace49587094ffe2aef7465601085d587`): локальный Vosk, потоковый аудиоклиент и ALSA. Исходный проект использует Claude Messages API и ElevenLabs, а не Claude Code. Здесь клиент Go подключается к OpenAI Realtime API по WebSocket; Vosk используется только для локального слова активации. Патч часов усилителя через /dev/mem из исходного проекта не применяется; используется ранее проверенный PCM `speakers`.

## Управление

```sh
/data/opt/bin/gpt-live start
/data/opt/bin/gpt-live status
tail -F /tmp/gpt-live.log
/data/opt/bin/gpt-live stop
```

После сообщения `Realtime connected` скажите: **«Компьютер, сколько будет два плюс два?»**. Можно отдельно сказать «Компьютер», затем произнести вопрос. После ответа можно произнести следующую реплику в течение 20 секунд без wake-слова; каждая реплика продлевает это окно, а после паузы колонка возвращается к ожиданию слова «Компьютер». Все реплики идут в ту же Realtime-сессию, поэтому модель сохраняет контекст разговора, пока работает сервис и WebSocket-соединение.

## Кнопки и световое кольцо

Сенсорные «+»/«−» управляют ALSA Master с шагом 5 процентных пунктов; удержание поддерживается с ограничением повторов. Обработка кнопок идёт отдельно от запросов и воспроизведения. Зелёные сегменты на секунду показывают громкость (при нуле — один тусклый красный сегмент). На цифровом дисплее две секунды отображается значение громкости от 0 до 100 в процентах, без ведущих нулей. Новое нажатие продлевает показ. Затем восстанавливаются прежняя яркость сегментов и LED triggers.

Кольцо показывает состояния: тусклое белое пульсирование при загрузке; голубой после распознавания слова обращения; оранжевое пульсирование во время ответа; зелёный во время проигрывания; красный на 2 секунды при ошибке. В ожидании кольцо выключено. Во время 20-секундного окна продолжения циферблат показывает `CALL`; вне окна восстанавливается штатное отображение времени. Показ громкости временно перекрывает этот индикатор. Предварительное распознавание может ошибиться: само по себе оно не отправляет аудио в API.

Контроллер `aw933xx` обнаруживается через sysfs, резервный путь `/dev/input/event1`. `MINI3_INPUT_DEVICE` позволяет указать другой путь. Клиент собран для aarch64 и читает 24-байтные input_event. `MINI3_LED_ROOT` меняет корень `/sys/class/leds` для диагностики. Управляются только `bergamot:{red,green,blue}:logo0..5` и trigger синхронизации кольца. Для временного показа громкости также используются сегменты `bergamot:white:clock*`; после показа они восстанавливаются. Штатные LED triggers временно отключаются и восстанавливаются при штатной остановке сервиса.

Сервис временно останавливает Алису, выставляет PDM Gain 36, включает zram при необходимости. После остановки возвращает Алису, если она работала. Автозагрузка пока не включена. Одновременный запуск с `vosk-live`/`vosk-test` запрещён.

Голосовой цикл: `gpt-realtime-2.1` через WebSocket, вход и выход — PCM 24 кГц; воспроизведение идёт на 48 кГц стерео. Голос `coral`, сгенерирован ИИ. Запросы выходят с колонки через её WireGuard. TLS проверяет сертификаты; обход проверки не используется. Контекст хранится в активном сеансе и сбрасывается при остановке сервиса или потере соединения.

Ключ: `/data/opt/openai/key.txt`, каталог 700, файл 600. В исходниках, аргументах команд и журналах ключа нет. Не публикуйте локальный `openai-key.txt`. Путь можно изменить через `OPENAI_KEY_FILE`, модель Realtime через `OPENAI_REALTIME_MODEL`, голос через `OPENAI_VOICE`, слово обращения через `OPENAI_WAKE_WORD` (одно слово в нижнем регистре).

Vosk распознаёт слово обращения локально. После срабатывания в Realtime отправляется буфер до 2,4 секунды (чтобы не обрезать само обращение), затем аудио вопроса; PCM 16 кГц преобразуется в 24 кГц. После ответа Vosk временно остаётся в режиме полной речи, а аудио следующей реплики направляется в ту же Realtime-сессию. Окно продолжения длится 20 секунд после ответа и продлевается, пока пользователь говорит; по истечении Vosk возвращается к локальной грамматике wake-слова. Во время ответа файл `/tmp/mini3-openai-mute` заставляет Vosk отбрасывать звук динамика. Аудиозаписи локально не сохраняются. Временный журнал ограничен примерно 1 MiB (и одна предыдущая копия). Не более 6 реплик в минуту. Автоматических повторов платных запросов нет.

## Настройки моделей и слова обращения

Файл на колонке: `/data/opt/openai/config.json`. Образец в репозитории: `config/openai.json.example`.

```json
{
  "model": "gpt-4.1-mini",
  "realtime_model": "gpt-realtime-2.1",
  "tts_model": "gpt-4o-mini-tts",
  "voice": "coral",
  "wake_word": "компьютер"
}
```

`realtime_model` — модель голосового сеанса, `voice` — голос, `wake_word` — локальное слово активации. Регистр слова нормализуется; слово должно присутствовать в словаре установленной модели Vosk. `model` и `tts_model` используются только командами без микрофона `ask`, `say` и `talk`.

Проверить итоговые настройки без запроса к API: `/data/opt/bin/mini3-openai config`. Затем применить изменения:

```sh
/data/opt/bin/mini3-openai config && /data/opt/bin/gpt-live stop
# Дождитесь завершения остановки (исчезнет /tmp/mini3-gpt-live).
/data/opt/bin/gpt-live start
```

Файл читается при каждом запуске клиента. Если стандартного файла нет, используются значения по умолчанию. Неизвестные поля и некорректный JSON дают ошибку. Другой путь задаётся через `OPENAI_CONFIG_FILE`; явно указанный файл должен существовать. Переменные `OPENAI_MODEL`, `OPENAI_REALTIME_MODEL`, `OPENAI_TTS_MODEL`, `OPENAI_VOICE`, `OPENAI_WAKE_WORD` имеют приоритет над файлом. API-ключ остаётся отдельно в `key.txt`.

## Команды без микрофона

```sh
/data/opt/bin/mini3-openai ask 'Ответь кратко: сколько будет два плюс два?'
/data/opt/bin/mini3-openai say 'Это синтезированный голос.'
/data/opt/bin/mini3-openai talk 'Почему небо голубое?'
```

`say` и `talk` отдельно не заглушают работающий голосовой сервис; для ручных тестов сначала остановите `gpt-live`.

## Исправление Vosk

В журнале ядра подтверждён OOM предыдущего постоянного распознавателя: система убила `vosk-stream` и `arecord`. Новый клиент сбрасывает распознаватель после каждого результата и не позже 15 секунд аудио, чтобы ограничить размер одной сессии декодирования. Увеличен запрашиваемый ALSA-буфер до 1 секунды, период 20 мс; фактические значения зависят от драйвера. Чтение аудио выполняется блоками, FIR использует float. Длительную стабильность нужно оценивать отдельно, короткий тест её не гарантирует.

## Проверки

`go test ./...` прошёл на сборочном сервере. На колонке проверена полная цепочка: синтетическая фраза воспроизведена через динамик, Vosk активировал локальное слово «алёша», Realtime вернул и озвучил ответ «Четыре. Это классика: два плюс два равно четыре». Следующая реплика «а если к результату прибавить пять?» в том же сеансе получила ответ «Было четыре, плюс пять — получаем девять». После обоих ответов сервис остался запущен и вернулся в ожидание.

При старте Vosk остаётся предупреждение о версии `libstdc++` из `libvosk.so`; в проверке оно не помешало распознаванию.
