# Безопасность и приватные данные

Не публикуйте секреты и персональные данные в issues, PR или Discussions. Перед публикацией проверяйте staged diff и содержимое логов. `.gitignore` помогает, но не проверяет содержимое исходников и не удаляет уже закоммиченные файлы.

Храните локально и вне Git API-ключи, SSH private keys, WireGuard PrivateKey/PresharedKey, заполненные `network.conf`/`wg0.conf`, `.env`, конфиги Wi-Fi, адреса личных сервисов, дампы и записи голоса.

Если секрет был опубликован, сначала отзовите/замените его. Простое удаление файла из последнего коммита не очищает историю. Переписывание веток также не удаляет чужие клоны и форки; GitHub может удерживать старые коммиты по SHA. При необходимости очистки серверных ссылок и кэшей обратитесь в [GitHub Support](https://support.github.com/) — решение о такой очистке принимает GitHub.

Если проблема относится к безопасности проекта, используйте приватное сообщение владельцу или вкладку Security → Report a vulnerability, если она включена. Не публикуйте действующие ключи даже в приватном отчёте.

Помощник выполняется с root-правами на устройстве. Сетевые конфиги исполняются shell как root. Репозиторий не содержит универсального безопасного установщика прошивки; сначала изучите команды и сделайте локальные резервные копии.
